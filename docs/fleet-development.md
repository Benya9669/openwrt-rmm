# Развитие управления парком

Пункты 1–9 доступны в разделе «Управление парком». При разработке использовались
тестовые базы и агенты; рабочие роутеры и production-конфигурация не менялись.

1. Массовые операции: явный список устройств или группа/теги, атомарная проверка
   доступа, постоянная очередь, лимит параллельности, результаты по устройствам,
   отмена ещё не запущенных команд. Backup использует существующее шифрованное
   хранилище. Выполняющаяся команда не считается остановленной при отмене очереди.
2. Профили UCI: эталон, проверка отклонений, preview, предварительный backup,
   canary, остановка при ошибке и подтверждаемый commit с откатом. Секретные
   значения не публикуются в сравнении.
3. Политики SSH/LuCI: разрешённые пользователи и устройства, разрешённые типы
   доступа, максимальное время сессии, единая проверка всех путей создания доступа
   и аудит. Существующая изоляция владельцев сохраняется.
4. Сравнение backup: добавленные, удалённые и изменённые файлы по manifest/хешам;
   содержимое конфигурации и секретов не выводится. Проверка текущего состояния
   выполняется отдельной читающей командой агента.
5. Планировщик: часовой пояс, дни недели, время и окно обслуживания, постоянная
   история запусков, защита от дублей и пропущенных запусков после перезапуска.
6. История: существующие CPU/RAM/WAN samples плюс события reboot, WAN IP и
   доступности в общей временной шкале, ограниченное хранение.
7. Диагностика: DNS, ping, маршрут, интерфейсы, время и сервисы; ограниченные
   по времени читающие проверки, результаты и явные выводы по каждой проверке.
8. Автоматические реакции: условия, число последовательных нарушений, cooldown,
   лимит повторов, журнал. Перезапуск разрешается только для выбранного сервиса;
   правило включается пользователем явно и не создаёт произвольный shell.
9. Учёт оборудования: модель, серийный номер, площадка, ответственный, гарантия,
   заметки, поиск и фильтры с прежними границами доступа к устройствам.

Основа: версионированная миграция для SQLite/PostgreSQL, durable operation queue,
подписанные команды, проверки авторизации и существующие UI primitives из DESIGN.md.
API и интерфейс используют прежнюю авторизацию и CSRF-защиту. Тесты проверяют
повторный запуск worker, независимые PostgreSQL-пулы, отмену, чужие устройства,
ограничения, миграцию старой базы и восстановление зашифрованных профилей.

## Установка и проверка

Обновите сервер обычным способом с сохранением БД, ключей подписи и ключа
шифрования. PostgreSQL получает миграцию 2 (`fleet.sql`); опубликованная миграция
1 не изменяется. SQLite добавляет таблицы при старте. Старые SQLite snapshots
импортируются без записи в исходный файл; частичная новая схема отклоняется.
Проверку recovery запускайте версией `rmm-db-verify`, соответствующей серверу.

Установите новый Go-агент сначала на тестовый роутер. Heartbeat должен объявлять
`diagnostic_report`, `remote_access_modes`, `uci_profile_preview`,
`uci_profile_apply`, `uci_profile_rollback` в `inventory.rmm_features`.
Старый агент сохраняет прежние команды; новые функции требуют соответствующей
возможности и не подменяются небезопасным fallback.

Начните с ping или диагностики одного устройства. В массовых операциях проверьте
его результат, затем увеличьте выбор. Лимит — 100 устройств, параллельность 1–20,
не более 20 активных операций пользователя. Обычная очередь живёт максимум 24
часа. Отмена удаляет оставшуюся работу и отменяет ожидающие команды; уже выданная
команда заканчивает работу на роутере. Доступ проверяется и перед выдачей команды.

Расписания и правила по умолчанию выключены. Для проверки сначала сохраните
выключенную запись, проверьте часовой пояс, дни и действие, затем включите её.
Worker запускается вместе с сервером; отдельный cron не требуется.

## Профили UCI и откат

Профиль задаёт одну конфигурацию (`system`, `network`, `wireless`, `dhcp`,
`firewall`) и 1–32 параметра. Формат в UI: `section.option=value`, например
`@system[0].hostname=branch-router`. Разрешены именованные секции и положительные
индексы анонимных секций. Пароли, ключи и другие credential-параметры исключены
из профилей; для них используется существующий процесс управления доступом.
Определение шифруется настроенным ключом данных сервера.

Preview читает параметры и фиксирует hash файла, определение профиля и срок
действия 30 минут. Он не вызывает `uci set`/`revert` и не стирает чужой staging.
Применение требует успешного preview каждого устройства и неизменного файла.
Если уже есть staged-изменения, операция отказывается от записи.

Перед изменением агент сохраняет файл с правами 0600 и постоянный журнал в
`COMMAND_STATE_DIR/profiles`. После commit он перезагружает соответствующий сервис
и через 15 секунд проверяет HTTPS-доступность сервера. При ошибке возвращается
сохранённая конфигурация. Незавершённый журнал восстанавливается при следующем
старте агента. Не меняйте ту же UCI-конфигурацию вручную во время применения.

Первое устройство — canary: после его результата очередь приостанавливается.
Проверьте связь и результат и нажмите «Продолжить очередь». «Откатить профиль»
восстанавливает локальный backup только если файл после применения не изменялся.
Локальные backup сохраняются; учитывайте свободное место на flash роутера.
Серверная отмена очереди сама по себе не откатывает выполненную конфигурацию.

## Политики доступа

Администратор задаёт для устройства SSH/LuCI, TTL 60–7200 секунд и, при
необходимости, список пользователей. Политика не расширяет владение устройствами:
пользователь всё равно должен иметь обычный доступ к объекту. Проверяются создание
сессии, managed-команды, LuCI-гранты и HTTP proxy. SSH сохраняет штатную
аутентификацию роутера; эта политика управляет открытием RMM-туннеля.

Изменение закрывает старые сессии, отзывает LuCI grants/cookies и отменяет
невыданные startup-команды. Tunnel reaper снимает listener по существующему
механизму отзыва. При запрете одного режима новый агент вообще не создаёт его
forwarding. Произвольная `remote_ssh_reverse` через generic command API запрещена;
используйте managed session API. Порты, PID namespace и Compose privileges
этой доработкой не меняются.

## Расписания, история и реакции

Расписание хранит календарь IANA, дни 0 (воскресенье) — 6, время начала в минутах
и окно 1–1440 минут. DST сохраняет местное время; несуществующее время пропускается,
повторённое выполняется один раз. Перезапуск вне окна отмечает запуск `missed`.
Подписанная команда ограничена сроком окна; уже начатая работа может завершиться
позже. Изменение/отключение расписания отменяет старые pending reservations,
но уже созданные операции отменяются отдельно.

Обновление агента фиксирует совместимую версию из настроенного подписанного
HTTPS feed при сохранении расписания. URL от клиента не принимается. Изменение
платформы требует пересохранить расписание; установленная версия пропускается.
Завершение требует heartbeat с новой версией, а не только успешной установки
пакета. Новую целевую версию выбирают пересохранением расписания.

История показывает последние 500 samples: CPU load average (LA1), RAM, WAN RX/TX,
изменения IP, уменьшение uptime и аудит. Пропуски heartbeat больше 120 секунд
дают оценку наблюдаемой доступности, не доказательство отключения роутера.
Скорость WAN не вычисляется через перезагрузку, сброс счётчиков или пропуск данных.
Хранение samples контролируется прежним `RMM_METRIC_RETENTION_DAYS` (по умолчанию 30).

Правило может проверять RAM, CPU load, недоступность всех connectivity checks,
отсутствие heartbeat или подтверждённую остановку сервиса по свежей диагностике.
Нужны 1–20 новых последовательных наблюдений; повтор worker не считает один sample
несколько раз. Неизвестные значения не считаются нарушением. Для offline один
новый observation соответствует минуте; service-down требует новых отчётов
диагностики (можно использовать расписание).

Действия — уведомление в центре событий или restart только `dnsmasq`/`uhttpd`.
Cooldown 300–86400 секунд, дневной лимит 1–5 действий в UTC. Команда restart живёт
5 минут, не повторяется автоматически и проверяет условие снова перед выдачей.
Восстановление отменяет ещё не выданный restart; отключение правила отменяет его
ожидающие команды. Журнал показывает queued/completed/failed/cancelled.

## API

Все пути ниже требуют operator session/token. Для изменений через cookie-сессию
сохраняются SameSite cookies и серверная проверка того же Origin.

| Путь | Назначение |
| --- | --- |
| `GET/POST /api/fleet/operations` | Очереди; POST: `request_key`, `device_ids` или `group`/`tag`, `type`, `args`, `parallelism`, `stop_on_failure` |
| `POST /api/fleet/operations/{id}/cancel` или `/resume` | Управление очередью |
| `GET/POST /api/fleet/profiles`, `PUT .../{id}` | Профили владельца |
| `POST /api/fleet/profile-operations` | `profile_id`, `action=preview/apply`, `device_ids`, `request_key`, `parallelism`; для apply — `preview_operation_id` |
| `GET/PUT /api/fleet/access-policies/{device_id}` | Политика; PUT только admin |
| `GET/POST /api/fleet/schedules`, `PUT .../{id}` | Расписания и последние 100 запусков |
| `GET /api/fleet/history/{device_id}` | Метрики и общая временная шкала |
| `GET/POST /api/fleet/rules`, `PUT .../{id}` | Правила и последние 100 реакций |
| `GET /api/fleet/assets?q=...&site=...`, `PUT .../{device_id}` | Учёт и фильтрация оборудования |
| `GET /api/devices/{id}/backups/{backup_id}/compare?against={other_id}` | Изменённые пути/размеры без содержимого файлов |

Для сетевого повтора POST operations/schedules/rules используйте тот же
`request_key` и тот же payload. Другой payload с этим ключом отклоняется.
Запрос с новым ключом создаёт отдельную запись. Диагностика использует
`type=diagnostic_report`; результаты — в обычном command result. Время сообщается
как состояние часов; NTP-синхронизация не предполагается без отдельного измерения.

## Проверки

`go test ./...`, `go test -race` для store/HTTP/агента, `npm run check:web`,
`npx playwright test`. PostgreSQL CI 16/18 включает импорт, независимые пулы,
расписания и реакции; recovery test проверяет pg_dump/pg_restore, шифрование
профилей и подписи команд. UCI apply/rollback проверены с контролируемым runner;
перед эксплуатацией необходим canary на реальном OpenWrt с доступным SSH.

Расширение: [роли, инциденты, волны обновлений и карта сети](management-development.md).
